Quick Start | 快速开始

English

  • Copy config.example.yaml to config.yaml.
  • Create .local.json for provider secrets and local-only overrides.
  • Run go run . providers to check available DNS vendors.
  • Run go run . plan -config config.yaml before issuing.
  • Run go run . issue -config config.yaml to obtain certificates.

中文

  • 复制 config.example.yaml 为 config.yaml。
  • 创建 .local.json 保存厂商密钥和仅本地生效的覆盖配置。
  • 运行 go run . providers 查看支持的 DNS 厂商。
  • 在签发前先执行 go run . plan -config config.yaml。
  • 执行 go run . issue -config config.yaml 获取证书。

Commands | 命令

go run . providers
go run . plan -config config.yaml
go run . list -config config.yaml
go run . info -config config.yaml -name example-prod
go run . issue -config config.yaml [-name example-prod] [-force]
go run . renew -config config.yaml [-name example-prod] [-force]
go run . revoke -config config.yaml -name example-prod
go run . install-cert -config config.yaml -name example-prod
go run . deploy -config config.yaml -name example-prod
go run . version

Challenges | 模式

English

  • dns-01: default mode backed by vendor DNS providers.
  • http-01: local HTTP challenge server.
  • standalone: local HTTP server flow with standalone semantics.
  • webroot: writes ACME challenge files into webroot_path.
  • tls-alpn-01: local TLS-ALPN challenge server.

中文

  • dns-01：默认模式，依赖 DNS 厂商 provider。
  • http-01：启动本地 HTTP challenge 服务。
  • standalone：使用本地 HTTP 服务的 standalone 运行方式。
  • webroot：将 ACME challenge 文件写入 webroot_path。
  • tls-alpn-01：启动本地 TLS-ALPN challenge 服务。

Config | 配置

ca:
  directory_url: https://acme-v02.api.letsencrypt.org/directory

account:
  email: ops@example.com
  key_path: .acme/account.pem
  accept_tos: true

dns:
  provider: alicloud
  env:
    ALICLOUD_ACCESS_KEY: ${ALICLOUD_ACCESS_KEY}
    ALICLOUD_SECRET_KEY: ${ALICLOUD_SECRET_KEY}

certificates:
  - name: example-prod
    domains:
      - example.com
      - '*.example.com'
    output_dir: certs/example-prod
    challenge: dns-01
    http_bind: 0.0.0.0
    http_port: "80"
    tlsalpn_bind: 0.0.0.0
    tlsalpn_port: "443"
    webroot_path: ""
    install:
      key_file: /etc/nginx/ssl/example/privkey.pem
      fullchain_file: /etc/nginx/ssl/example/fullchain.pem
    deploy:
      - name: edge-copy
        type: copy
        directory: deploy/example
      - name: reload-nginx
        type: command
        command: nginx -s reload
    hooks:
      pre_issue: []
      post_issue: []
      pre_renew: []
      post_renew: []
      post_install: []
      post_deploy: []
      post_revoke: []

Deploy and Hooks | 部署与钩子

English

install copies certificate files into fixed paths. deploy currently supports copy and command targets. Hooks can run before or after issue, renew, install, deploy, and revoke operations.

Common env vars: ACME_CERT_NAME, ACME_CERT_FULLCHAIN_FILE, ACME_PROVIDER, ACME_CHALLENGE, ACME_DEPLOY_TARGET.

中文

install 会把证书复制到固定路径。deploy 当前支持 copy 与 command。Hooks 可在 issue、renew、install、deploy、revoke 的前后执行自定义命令。

常用环境变量：ACME_CERT_NAME、ACME_CERT_FULLCHAIN_FILE、ACME_PROVIDER、ACME_CHALLENGE、ACME_DEPLOY_TARGET。

Release | 发布

English

The tag-based GitHub Actions release workflow builds archives for Linux, Windows, and macOS on amd64 and arm64, bundles docs, and publishes checksums.

git tag v1.0.0
git push origin v1.0.0

中文

基于 tag 的 GitHub Actions 发布流程会为 Linux、Windows、macOS 的 amd64 与 arm64 构建压缩包，附带文档，并发布校验和文件。

git tag v1.0.0
git push origin v1.0.0
