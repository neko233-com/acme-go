acme233 Usage Guide

acme233 obtains and renews free SSL certificates through ACME. It is driven by config_acme.json, and private DNS credentials should be placed in config_acme.local.json.

Quick Start

  1. Choose a supported DNS provider that hosts your domain.
  2. Create an API token or access key with permission to edit DNS TXT records.
  3. Put public certificate settings in config_acme.json.
  4. Put private credentials in config_acme.local.json.
  5. Run acme233 validate -config config_acme.json.
  6. Run acme233 issue -config config_acme.json -name neko233-staging.
acme233 providers
acme233 validate -config config_acme.json
acme233 paths -config config_acme.json -name neko233-staging
acme233 issue -config config_acme.json -name neko233-staging

Prepared Domain

The prepared wildcard test certificate entry is neko233-staging. It requests _.neko2public.online, which represents the wildcard domain for local filesystem-safe output. The output directory is:

output_SSL/_.neko2public.online/

After issuance, the directory contains cert.pem, privkey.pem, pubkey.pem, fullchain.pem, issuer.pem, and metadata.json.

Using the Certificate

nginx

ssl_certificate     /path/to/acme233/output_SSL/_.neko2public.online/fullchain.pem;
ssl_certificate_key /path/to/acme233/output_SSL/_.neko2public.online/privkey.pem;

Caddy

tls /path/to/acme233/output_SSL/_.neko2public.online/fullchain.pem /path/to/acme233/output_SSL/_.neko2public.online/privkey.pem

Windows or GUI tools

Use fullchain.pem as the certificate chain and privkey.pem as the private key. Keep output_SSL/ backed up but do not commit it to Git.

Example Local Secret File

{
  "account": { "email": "ops@example.com" },
  "dns_providers": {
    "aliyun-cn": {
      "credentials": {
        "access_key": "your-access-key",
        "secret_key": "your-secret-key"
      }
    }
  }
}
